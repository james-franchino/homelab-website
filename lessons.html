Learning through experience

What the lab has taught me.

Building the lab involves more than installing applications. Keeping those applications useful means investigating problems, protecting data, and understanding how the pieces fit together.

Check where the problem actually starts

After a macOS update, Vivaldi could no longer open some of my local services. The same addresses still worked in Safari. That comparison helped narrow the problem to the browser or its permissions.

Checking macOS settings revealed that Vivaldi's local network permission was not enabled, even though I had approved the permission prompt. Enabling it restored access.

The lesson

An unreachable service does not automatically mean the server has failed. Testing from another browser or device can help identify which part of the connection needs attention.

Backups are part of running a service

My lab stores photos, documents, and application data that I care about. Protecting that information requires more than keeping the servers running. My backup setup includes scheduled copies of important data and off-site storage.

Applications can also depend on more than their visible files. For example, my Immich backup plan includes its database as well as the photo files. Both matter when planning a recovery.

The lesson

A backup plan should identify what needs to be saved and how it would be restored. Drive protection alone cannot cover every situation, such as accidentally deleting a file.

Configuration details matter

Running applications in Docker involves deciding where their data lives, how they connect to the network, and which settings they need. A container starting successfully is only one part of getting a service working.

Docker Compose gives me a place to record these settings. Understanding the configuration helps me troubleshoot a service and see how it connects to the rest of the lab.

The lesson

Copying a configuration is a starting point. Understanding its paths, ports, and settings makes it easier to adapt and maintain.

Monitoring provides useful clues

Tools such as Uptime Kuma, Grafana, and Prometheus help me observe my systems. Availability checks show whether services respond, while metrics show how resources are being used.

Logs provide another view by recording events and error messages. Together, these tools give me information to investigate when something behaves unexpectedly.

The lesson

Monitoring does not fix a problem by itself, but it provides evidence that can guide the next troubleshooting step.

Practical work gives classroom concepts meaning

Studying Linux introduces commands and concepts. Using them on my own server connects those ideas to actual tasks, such as managing files, checking services, and reading logs.

The lab gives me reasons to keep practicing. Each application I maintain creates another opportunity to understand the system supporting it.
